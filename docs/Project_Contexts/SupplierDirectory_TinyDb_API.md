## Data model contract

### Required persisted fields

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | Supplier / vendor display name |
| `country` | `string` | Contract country — exactly `USA` or `UK` |
| `categories` | `list[string]` | One or more categories from the allowed set below |
| `monthly_rate` | `number` (float) | Current monthly cost in the contract currency; **must be > 0** |
| `currency` | `string` | `USD` when country is `USA`, `GBP` when country is `UK` |
| `updated_at` | `string` (ISO 8601 datetime) | Last change timestamp; **system-generated only** |
| `status` | `string` | Supplier status from the allowed set below |

TinyDB also assigns an integer document `id` on insert. Responses must include `id`.

### Allowed statuses

- `active`
- `suspended`

Values outside this set must be rejected with **HTTP 422** before data reaches TinyDB. Use an Enum or a field validator.

### Allowed product categories

- `MEDICAL_SUPPLIES`
- `LAB_CONSUMABLES`
- `PPE`
- `PHARMACEUTICALS`
- `IT_EQUIPMENT`
- `FACILITIES`
- `DIAGNOSTIC_EQUIPMENT`

### Allowed countries

- `USA`
- `UK`

Use an Enum or Literal. Any other `country` value must be rejected with **422**.

### Allowed currencies

- `USD` — required when `country` is `USA`
- `GBP` — required when `country` is `UK`

A mismatched pairing (for example `USA` + `GBP`) must be rejected with **422**.

### Validation rules

- `monthly_rate` must be a **positive** number. Zero or negative values must be rejected with **422** before TinyDB.
- `status` must be exactly `active` or `suspended`.
- `country` must be exactly `USA` or `UK`.
- `currency` must be `USD` for `USA` and `GBP` for `UK`.
- `categories` must be a non-empty list; every element must be in the allowed category set.
- `status` is **required** on create (no server default).
- `updated_at` is generated by the system on create and whenever rate or status changes. Clients must **not** send `updated_at` on create or patch bodies.
- `id` is assigned by TinyDB; clients must not send `id` on create.

### Separate input and response models

| Model | Purpose | Fields |
|-------|---------|--------|
| `SupplierCreate` | Client body for `POST /suppliers` | `name`, `country`, `categories`, `monthly_rate`, `currency`, `status` — **no** `id`, **no** `updated_at` |
| `SupplierResponse` | API responses | `id`, `name`, `country`, `categories`, `monthly_rate`, `currency`, `updated_at`, `status` |
| `RateUpdate` | Body for `PATCH /suppliers/{id}/rate` | `{ "monthly_rate": number }` with `monthly_rate > 0` |
| `StatusUpdate` | Body for `PATCH /suppliers/{id}/status` | `{ "status": "active" \| "suspended" }` |

### Persistence

- TinyDB file path (shared by seeder and API): **`services/api/data/suppliers.json`**
- Data must survive server restarts.
- When implementation lands, gitignore the generated JSON file (`.gitignore` change belongs to the implementation stamp, not this CONTEXT).

### Endpoints (`services/api`)

Keep the existing Incident Analyzer routes intact on the same FastAPI app. CORS must allow `http://localhost:3001`.

#### HTTP status matrix

| Operation | Success | Error |
|-----------|---------|--------|
| `POST /suppliers` | **201** + `SupplierResponse` | **422** invalid body |
| `GET /suppliers` | **200** + list of `SupplierResponse` | — |
| `GET /suppliers/{id}` | **200** + `SupplierResponse` | **404** if missing |
| `PATCH /suppliers/{id}/rate` | **200** + updated `SupplierResponse` | **404** if missing; **422** if `monthly_rate <= 0` or invalid body |
| `PATCH /suppliers/{id}/status` | **200** + updated `SupplierResponse` | **404** if missing; **422** if status not allowed |
| `DELETE /suppliers/{id}` | **200** + `{"ok": true, "id": <deleted_id>}` | **404** if missing |

#### Route behaviour

- `POST /suppliers` — Register a new supplier. Return the created supplier with its TinyDB-assigned `id` and system `updated_at`. Reject invalid inputs with **422**.
- `GET /suppliers` — List suppliers. Optional query parameters: `country`, `category`.
  - No parameters → return all.
  - `country` alone → country equals that value.
  - `category` alone → value is in `categories`.
  - Both `country` and `category` → **AND** (must satisfy both).
- `GET /suppliers/{id}` — Return supplier details by ID. **404** if missing.
- `PATCH /suppliers/{id}/rate` — Update `monthly_rate`. Set `updated_at` at change time. Reject rates `<= 0` with **422**. **404** if ID does not exist.
- `PATCH /suppliers/{id}/status` — Activate or suspend. Accept only `active` / `suspended`. Reject others with **422**. Set `updated_at`. **404** if ID does not exist.
- `DELETE /suppliers/{id}` — Remove supplier. Success body: `{"ok": true, "id": <deleted_id>}`. **404** if missing.

## What We Will Evaluate

### Model and validation

- The Pydantic model reflects exactly the fields defined in this CONTEXT.
- `status` values outside `active` / `suspended` are rejected with **422** before TinyDB.
- `country` values outside `USA` / `UK` are rejected with **422**.
- `currency` that does not pair with country (`USA`/`USD`, `UK`/`GBP`) is rejected with **422**.
- `monthly_rate`: zero or negative values are rejected with **422**.
- `updated_at` is generated by the system, not sent by the client.

### Seeder

- `python seed.py` runs without errors and loads the CONTEXT suppliers into `data/suppliers.json`.
- Running the seeder more than once does not produce duplicates.
- The console prints exactly `Inserted N supplier(s).` when it finishes.

### Endpoints

- `POST /suppliers` creates a supplier and returns **201** with the complete object including `id`.
- `GET /suppliers` with no parameters returns all suppliers (**200**).
- `GET /suppliers?country=X` returns only suppliers from the specified country.
- `GET /suppliers?category=Y` returns only suppliers that provide that category.
- `GET /suppliers?country=X&category=Y` applies **AND** filtering.
- `GET /suppliers/{id}` returns **404** for non-existent IDs.
- `PATCH /suppliers/{id}/rate` updates `monthly_rate`, records `updated_at`, returns **200**; returns **404** if ID missing; **422** if rate `<= 0`.
- `PATCH /suppliers/{id}/status` rejects disallowed status values with **422**; returns **404** if ID missing.
- `DELETE /suppliers/{id}` returns **404** for non-existent IDs; on success returns **200** with `{"ok": true, "id": ...}`.

### Frontend

- The supplier list loads from the API and displays the fields defined in this CONTEXT.
- Country and category filters work and update the list without reloading the page.
- The registration form validates required fields on the client (`name`, `country`, `categories`, `monthly_rate`, `currency`, `status`) and displays the API error if the server rejects the input.
- Rate updates and status changes are reflected in the interface after the API responds.
- Active and suspended suppliers are visually distinguished.

### Cross-cutting

- TinyDB persists at `services/api/data/suppliers.json`: data remains after restarting the server.
- HTTP errors are consistent: **404** when not found, **422** when input is invalid, **200**/**201** when the operation succeeds (POST create = **201**).
- Incident Analyzer routes on the same API remain functional; CORS allows the backoffice origin.
- Code is organized according to the monorepo folder structure (`services/api` for the backend, `uis/backoffice` for the frontend).

## How to run

Run commands from the paths shown. Implementation ships in a later plan stamp; these commands are the target contract.

```bash
cd services/api
python -m pip install -r requirements.txt
python seed.py
```

Writes/reads `services/api/data/suppliers.json`. Console must print e.g. `Inserted 15 supplier(s).` on a fresh DB.

```bash
cd services/api
python -m uvicorn app.main:app --reload --port 8001
```

Health check: http://localhost:8001/health  

Supplier routes (examples):

- `GET http://localhost:8001/suppliers`
- `GET http://localhost:8001/suppliers?country=USA`
- `GET http://localhost:8001/suppliers?category=PPE`

```bash
cd uis/backoffice
npm install
npm run dev
```

Open http://localhost:3001/suppliers (after the page is implemented). Default API base: `http://localhost:8001` via `NEXT_PUBLIC_SUPPLIERS_API_URL` (same host/port pattern as the Incident Analyzer).
